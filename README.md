# Backtrack: Dual N-Back PWA

An installable, offline-first dual n-back trainer for iOS, Android and desktop.
TypeScript + Vite, no UI framework, no runtime dependencies.

## Commands

```bash
npm install          # Node >= 20.19
npm run dev          # dev server with hot reload  → http://localhost:8765
npm test             # unit tests (Vitest)
npm run typecheck    # tsc, strict mode
npm run build        # typecheck + production build into dist/
npm run preview      # serve dist/ (service worker active) → http://localhost:8765
npm run icons        # regenerate public/icons/
```

`.npmrc` sets `legacy-peer-deps=true` to avoid an npm 10.8 crash
(`Cannot read properties of null (reading 'edgesOut')`) on Vite 8's optional peers.

## Deploy

`npm run build`, then upload `dist/` to any static HTTPS host (GitHub Pages, Netlify,
Cloudflare Pages, Vercel). The build uses relative paths, so a sub-path works too.

- **iOS (Safari):** Share → *Add to Home Screen*.
- **Android (Chrome):** menu → *Install app*.

The service worker is generated by `vite-plugin-pwa` (Workbox) with content-hashed
precaching, so updates install automatically on the next launch.

## Architecture

```
src/
  main.ts                 composition root: builds services, wires views
  domain/                 pure logic, no DOM or storage; shareable with a backend
    types.ts              Round, Settings, Profile, ProgressSnapshot
    engine.ts             sequences, scoring, levelling, days/streaks
    stats.ts              statistics derived from the round log
  data/                   persistence
    repository.ts         ProgressRepository interface (the storage boundary)
    localStorageRepository.ts   current implementation (device only)
    schema.ts             defaults, validation, versioned migrations
    ids.ts                UUIDs (with a non-HTTPS fallback)
  state/appStore.ts       app state + actions; the only writer to the repository
  services/               browser APIs: speech.ts (Web Speech), wakeLock.ts
  ui/                     DOM only
    router.ts, dom.ts, charts.ts, debug.ts, context.ts
    views/                home, play (round loop), result, stats, settings
tests/                    Vitest: engine, schema migrations, store + repository
```

Dependencies point inward: `ui → state → data → domain`. `domain` imports nothing.

### Ready for a backend

Storage sits behind `ProgressRepository` (async), and `main.ts` is the only place
that chooses an implementation. The data model is already sync-friendly:

- **Rounds are append-only** with client-generated UUIDs, so uploads are idempotent
  (re-sending a round can't duplicate it) and two devices never conflict.
- **Level, streaks and stats are derived** from rounds, so they never need syncing.
- **Profile and settings carry `updatedAt`** for last-write-wins merges.
- **`schemaVersion` + `parseSnapshot`** validate and migrate any stored or imported
  data; old v1 data from the first JS version migrates automatically on load.

Adding a backend later means writing a `SyncedRepository` (write locally first,
upload pending rounds in the background, pull on login) and swapping it in `main.ts`.
`src/domain/types.ts` can double as the API contract.

## Game rules

| Rule | Value | Source |
|---|---|---|
| Stimuli | 3×3 grid position + spoken letter | observed |
| Rounds per daily session | 12 (≈20 min) | observed |
| Challenge length | 20 days | observed |
| Level up / down | both ≥ 90% / either < 75% | observed |
| Level range | 1–14 | observed |
| Day rollover | 4 AM | observed |
| Max speed (non-scientific mode) | 4× | observed |
| Steps per round | 20 + n | design choice (Jaeggi protocol) |
| Step timing | 3 s, stimulus visible 0.5 s | design choice (Jaeggi protocol) |
| Targets per round | 6 position + 6 sound (2 dual) | design choice (Jaeggi protocol) |
| Score | hits ÷ (hits + misses + false alarms) | design choice |
| Letters | C H K L Q R S T, spoken (English or pt-BR), spoken + written in the square, or written only (silent mode) | design choice |

"Observed" rules come from the string table of the reference app's Hermes bytecode
(N-Back Challenge 1.13.6); its code wasn't decompiled. No code, text, branding or
audio from it is used.

## Speech debugging

Open the app with `?debug` (e.g. `http://localhost:8765/?debug`) to show a live panel
with the active voice, engine state and any stalled or failed letters. The speech
service recovers from paused/wedged engines with a 1 s watchdog that resets and
replays the letter.
